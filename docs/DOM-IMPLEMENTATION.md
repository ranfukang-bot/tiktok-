# TikTok Studio 跨语言改造交接

## 实现方式

本次改造使用已登录页面的 DOM 语义，不是直接调用 TikTok 私有 HTTP 发布接口。
主实现位于 `src/browser/injected.js`，仍由 `src/browser/tiktokStudio.js` 通过 CDP 编排。

- 上传：`upload_status_container` 内 `.info-progress` 和 `.info-status` 均为 `success`，然后等待默认标题稳定。
- 文案：保留真实鼠标聚焦、Ctrl+A / Backspace 清空、真实鼠标点 `.suggest-item` 的已修复路径。
- 商品：`.anchor-tag-container` → `.anchor-modal`（商品类型33）→ `.product-selector-modal` → 精确商品 ID 行 → 选中 radio → 商品名确认 → 锚点核对。每一步都限制容器和主按钮，未知结构不猜。
- AI：`aigc_container` 内开关；先通过 `advanced_settings_container .more-btn` 展开。兼容首次开启时的说明确认框，只接受本次点击触发且匹配已验证结构的弹窗。
- 发布时间：`input[name="postSchedule"][value="post_now"]`，点击后核对 checked。
- 检查：分别读取音乐和内容两个区域。排除 `data-show="false"`、隐藏节点和隐藏祖先，只认可当前可见的 `status-success` 加成功色标记。任一红/黄/关闭立即停止，未完成或未知状态最多等10分钟，超时不放行。
- 发布：仅定位 `post_video_button`。等待阶段和最终点击当下各核对一次安全条件；任何可见弹窗均阻挡，点击发布后出现新弹窗按结果不确定处理，绝不自动确认。
- 控制台：移除15项文案表单及保存/运行前的翻译必填校验。保留已有账号字段，不迁移或覆写用户配置。旧文案只有 `appCrashMarkers` 仍用于可选错误页诊断，不控制安全放行。

## 生效与范围

旧Node服务仍需手动重启（本次自动重启被环境策略阻止），然后刷新控制台。
启动入口仍是 `npm start`，自动发布由用户自行点击启动。

同一DOM版本可以跨语言复用；这不代表所有国家、所有账号权限或A/B版本均已验证。
缺少橱窗/历史标签、控件改版或检查不可用时会停止，不绕过平台检查。
