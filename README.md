# TikTok Studio 批量发布控制台

替代原来那份装在每个指纹浏览器里的油猴脚本(`TikTokStudioBulkUploadV2`)。

不用再改代码、不用敲命令：打开一个网页，账号、视频文件夹都在网页上填，点"启动自动发布"
就交给它自己跑。原理是这个网页背后的程序通过 比特浏览器(BitBrowser) / AdsPower / Hubstudio
的"本地API"连上你已经登录好、带好指纹的浏览器窗口，远程帮你操作 TikTok Studio——跟你自己
手动点是一样的效果，只是不用人盯着。原脚本里那些踩过坑的细节（安全清空默认文案、商品挂车
的多步弹窗、发布前检测、发布结果确认）都保留在里面。

> **选哪个指纹浏览器**：AdsPower 和 Hubstudio 的"本地API"都是付费团队版才能用的功能，免费版
> 会直接报错"无法使用API，请升级套餐"，这是它们的收费策略，不是这套工具的问题。**比特浏览器
> (BitBrowser) 免费版就能用**，如果你还没定下来用哪个指纹浏览器，优先选比特浏览器能省这笔钱。

## 第一次使用

1. 装一次 Node.js（如果电脑上没装过）：去 <https://nodejs.org> 下载"LTS"版本，一路下一步
   安装即可，跟装普通软件一样，装完不用管它。
2. 双击这个文件夹里的 **`start.bat`**（Windows）或 `start.command`（Mac）。
   第一次运行会自动装一些必需的组件，等一会儿；装完会自动打开浏览器网页。
3. 以后要用的时候，还是双击同一个文件启动就行。

打开的网页就是控制台，长这样：顶部"启动自动发布/停止"按钮、账号列表、下面是全局设置和
运行日志。所有操作都在网页上点，不需要再打开这份代码。

## 添加账号

网页上点"+ 添加账号"，填：

- **账号名称**：随便起，用来区分，比如"马来一号"。
- **用哪个指纹浏览器**：比特浏览器 / AdsPower / Hubstudio。
- **环境ID**：
  - 比特浏览器：选它之后旁边会出现一个"从列表选择…"下拉框，直接按账号名字选，会自动
    把ID填进去，不用自己去找。如果下拉框读取失败，再去比特浏览器"浏览器窗口"列表里核对。
  - AdsPower：环境列表里那一串数字ID（截图里"序号"旁边那个）。
  - Hubstudio：环境的 containerCode（这个可以在 Hubstudio 客户端的环境详情里看到）。
- **视频文件夹**：点"浏览…"弹出选择框选一个文件夹（Windows支持），或者直接从文件资源
  管理器地址栏复制路径粘贴进去。文件夹里视频的**文件名就是商品ID**，比如 `123456.mp4`。
  **确认发布成功后，这个文件会被移到回收站**（全局设置里可以关掉），所以文件夹本身
  就是"待发布清单"：里面还有视频就是没发完，空了就该加新的了，不用对照进度列表猜。
  是移到回收站不是永久删除，误删还能捞回来；目前只支持 Windows。
- **话题标签**：要依次点击的历史话题，逗号分隔，默认 `fyp,tiktok,tiktokshop`。
  > ⚠️ **新账号第一次用之前，必须先在 TikTok Studio 里手动发一条带上这些标签的作品**，
  > 让 TikTok 记住这几个"历史标签"。自动发布只会点文案框里弹出来的历史标签建议项，
  > 不会自己打字硬造——打出来的字TikTok不认，不是真正能被搜到的话题标签，试过了不管用。
  > 没有历史记录的话，账号会在这一步报错暂停，提示你先去手动发那一条。
- **TikTok Studio 界面文案**：见下面"换语言 / 换地区怎么配"一节。默认是印尼语，
  做别的地区必须改这里。

保存后账号就出现在列表里了，点"启动自动发布"就会开始按各账号自己的随机间隔轮流处理。

## 换语言 / 换地区怎么配

**先说结论：任何地区都能用，要改的只有"界面上的字"。**

程序找按钮分两种方式：

- **靠页面结构找**（class 名、`data-e2e` 这些）——TikTok Studio 全球是同一套代码做的
  多语言，这些东西不随语言变，**跨地区通用，不用动，也别去动**。
- **靠界面上的文字找**（"下一步""立即发布"这些按钮上的字）——这部分跟语言绑死，
  换语言就必须换。全部集中在账号编辑弹窗的「TikTok Studio 界面文案」里，共 15 项。

⚠️ 关键一点：**是看 TikTok Studio 显示的语言，不是看账号做哪个国家**。
做印尼但后台是英文界面，就按英文配。

### 怎么配

1. 编辑账号 → 「TikTok Studio 界面文案」→ 顶上选**这个账号的界面语言**：
   - **印尼语**：从真实界面扒下来的，15 项全都验证过，选完直接能用。
   - **英语**：只填了我们能确认的词，**版权/违规提示**和**商品弹窗里必然出现的字**
     这两项是空的，要你自己补（原因见下）。
   - **其它语言**：什么都不继承，15 项照着自己的界面从头填。
2. 打开这个账号的 TikTok Studio，对着界面把每个框里的字抄进去。每个框下面都写了
   "这段文字在哪能看到"。
3. 带 <kbd>必填</kbd> 标记的项没填完**保存不了**，会当场告诉你缺哪几项。

### 为什么英语预设是残缺的（这是故意的）

我们没有见过真实的英文 TikTok Studio 界面，所以不给那两项编翻译。

因为**编错的翻译比空着危险得多**：版权检测这一项只有在视频真被判违规时才会触发，
你跑一百条正常视频都验证不出它配得对不对。要是我们随手编了个 `"Copyright issue"`
而真实界面写的是别的，它就永远匹配不上——每条视频都被当成"检测通过"，
**保护静默关掉了，而界面上看着一切正常**。留空则会被拦住，逼你去把真实的字填对。

同理，选了非印尼语的预设，这个账号就**不再继承**全局那套印尼语文案。
不然你会看到一堆印尼文被当成"已经配好了"，实际在你的英文界面上一个都匹配不上。

### 配不全会怎么样

- **保存时**：必填项缺了直接拦住，不让存。
- **真跑起来时**：还会再自检一遍（手改过 `accounts.json` 也绕不过去），
  缺了就停下来通知你，**绝不会"检测不了就当没问题"往下发**。

## 每天自动发几条、什么时候刷新额度

全局设置里可以设"每个账号每天最多发几条"（比如 4 条），按你选的**时区**算一天的
边界——发够这个数今天就不再发了，账号那一行会显示"今日额度用完，等 Asia/Jakarta 的明天"（显示的就是你选的那个时区），
等那个时区过了0点，额度自动刷新，不用你手动做任何事。

时区下拉框里是完整的世界时区列表（400 多个），常用的跨境地区置顶了。
默认是 `Asia/Jakarta`（印尼西部时间 WIB），**做哪个地区就选哪个地区的时区**。

不管时段，只要程序在跑、文件夹里有视频、今天的额度还没用完，就会按正常的发布间隔
（"发布间隔 最短/最长"那两个设置）继续发。你只需要盯着文件夹里的视频够不够，
不够就加新的进去，剩下的全自动。

设成 0 表示不限制。

## 全局设置

网页上"全局设置"里可以调：

- 发布间隔（最短/最长，单位小时，默认 1.5~2.5 小时）
- 同时最多几个账号一起跑（建议先填 1，最稳妥）
- 比特浏览器 / AdsPower / Hubstudio 的本地API连接地址

**比特浏览器**：本地API地址在客户端"系统设置"里能看到，默认一般是
`http://127.0.0.1:54345`，连不上就去核对一下这个端口填的对不对。免费版就能用，接口路径
已经按官方文档接好了，正常不用改。

**Hubstudio**：接口路径已经按官方文档确认过了（`/api/v1/browser/start`）。如果客户端
「开发者」页面里的"安全校验"是开着的，把生成的 API Key 填到"全局设置 → Hubstudio连接
设置"里；关着的话不用填。

**AdsPower**：本地API是付费团队版专属功能，免费版会直接报错"Require api-key"或类似的
套餐限制提示——这种情况下升级套餐或者换用比特浏览器，代码这边没有能改的地方。

## 出问题时它自己怎么处理

不是一遇到问题就停下等你。程序会先判断这是"临时抽风"还是"真需要人管"：

- **临时问题**（页面加载超时、指纹浏览器客户端还没开、网络抖了一下、TikTok页面自己崩了）
  → **自己重试**，间隔 5分钟 → 15分钟 → 40分钟，全程不打扰你。账号那一行会显示
  "出错重试中"。三次都不行才会停下并通知你。
- **配置问题**（环境ID填错、视频文件夹不见了、界面语言对不上、指纹浏览器套餐限制）
  → 重试没意义，**立即暂停并通知你**，通知里会说明是配置问题。
- **需要你判断的**（发布结果不确定、版权违规、商品ID搜不到）
  → **立即暂停并通知你**，绝不自己乱试。

> **一条硬规则**：只要有可能已经点过发布按钮了，无论报什么错，都**绝对不会自动重试**——
> 重试一次就可能把同一条视频发两遍。这种情况一律停下来等你人工核实。

## 出问题时通知你

在"全局设置 → 出问题时通知我"里配置，支持四种推送方式，挑一个你顺手的：

| 推送方式 | 需要填什么 | 怎么拿 |
|---|---|---|
| **Telegram** | Bot Token + Chat ID | 找 `@BotFather` 建个机器人拿 Token；找 `@userinfobot` 发条消息拿 Chat ID |
| **企业微信群机器人** | Webhook 地址 | 企业微信群 → 群设置 → 群机器人 → 添加，复制地址（推到微信上，国内最方便） |
| **Bark** | 推送地址 | iPhone 装 Bark 这个 App，首页显示的地址复制过来 |
| **自定义 Webhook** | 一个 URL | 会往这个地址 POST 一段 JSON，方便你接自己的系统 |

配好之后**先点"保存全局设置"，再点"发送一条测试通知"**确认能收到。

只有真正需要你处理的时候才推送，而且同一次暂停只推一条，不会反复轰炸。

## 需要你看一眼网页的情况

- **"发布结果不确定"**：点了发布按钮后一直没检测到跳转成功，为了不重复发布，脚本会暂停
  这个账号，账号那一行会出现"确认已发布"/"确认未发布，重试"两个按钮。你打开对应的指纹
  浏览器看一眼 TikTok 后台的内容列表，点其中一个就行。
- **其它报错暂停**：账号那一行会显示暂停原因（比如某个按钮找不到、文案没清空干净），
  底部日志区能看到更详细的记录。排查完点"继续"恢复。

## 目录说明（不需要动，了解一下就行）

```
start.bat / start.command   双击启动
config/                     网页上的设置最终存在这里 (settings.json / accounts.json)
state/                      每个账号的发布进度，网页崩了/重启都不会丢
public/                     控制台网页本体
src/                        后台逻辑
test/                       回归测试（`npm test`）
```

改过代码之后跑一下 `npm test`。它守的是两条最容易被悄悄弄坏、又完全看不出来的底线：
现有印尼配置必须继续能跑；换了语言的账号绝不能继承印尼语的安全文案
（继承了的话版权检测会永远匹配不上，等于保护关掉了，但界面上一切正常）。
测试是纯函数 + 一个临时空白页，**不会动 `config/` 里你自己的配置**。

## 进阶：命令行方式（不需要网页界面的话）

如果你更习惯命令行，也可以不用网页，直接用 CLI：

```bash
npm install
cp config/settings.example.json config/settings.json
cp config/accounts.example.json config/accounts.json
# 编辑这两个 json 文件
npm run cli                                          # 启动全自动编排器（前台运行）
node src/index.js resolve "账号名" --published        # 人工确认上次其实发布成功了
node src/index.js resolve "账号名" --retry             # 人工确认上次没有发布，重试当前这条
```

两种方式用的是同一份 `config/*.json`，网页和命令行改的是同一份配置，不会冲突。
